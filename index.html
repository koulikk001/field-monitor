How this works — the dashboard only ever talks to this backend, never directly to the ESP32s. The backend proxies the camera feed and receives sensor readings pushed from the field node, which is what lets this page be viewed safely from anywhere (even https) while the hardware stays on a plain local network. Point the sensor node's firmware and the backend's config.json at each other — see the contract below.
Sensor node → backend POST <backend>/api/ingest Header: X-Device-Key: <ingestKey from config.json, if set> Body: { "device_id": "node-1", "co2_ppm": 480, "co_ppm": 3, "so2_ppm": 0.4, "smoke_pct": 6, "lat": 37.7749, "lon": -122.4194, "alt_m": 15.2, "gps_fix": true, "accuracy_m": 4, "battery_pct": 87, "timestamp": "2026-09-04T10:02:00Z" } Backend → dashboard WebSocket <backend>/ws (falls back to polling /api/latest) Camera backend proxies config.json's cameraStreamUrl at /api/camera/stream

Threshold colors are reference defaults (rough OSHA/EPA/WHO short-term exposure ranges for CO₂, CO and SO₂, and a generic obscuration scale for smoke), set once on the backend so every dashboard agrees. They give responders a fast visual read — this is not a certified gas-detection instrument. Follow your organization's protocols and certified equipment for go/no-go decisions.
